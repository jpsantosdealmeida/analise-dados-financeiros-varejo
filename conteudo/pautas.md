# Pautas e critérios de publicação

## GitHub

Registrar quando existir código relevante, decisão justificada, pergunta bem definida, evidência, mudança de método ou resultado reproduzível. Uma tentativa com limitação explícita também é útil.

## LinkedIn

Publicar aprendizados quando houver uma história concreta e tecnicamente correta. Para posts com números ou conclusões sobre o negócio, exigir fonte, consulta, denominador e revisão das limitações.

| Pauta | Estado | Próximo requisito |
|---|---|---|
| Meu JOIN gerou pares, não novas vendas | Rascunho preparado | Revisão do autor |
| Por que não removi todo CustomerID ausente | Pauta | Documentar impacto por métrica |
| Do Excel ao SQL Server preservando a origem | Pauta | Validar carga e obter evidência |
| Identificação do cliente e diferença de preço | Aguardar | Concluir comparação e robustez |
| Quantidade e preço unitário | Aguardar | Testar H2 e contraexemplos |
| Dashboard e decisões apoiadas | Futuro | Artefato funcional e métricas definidas |

Cada revisão deve classificar: documentar agora, rascunhar post, aguardar evidência. Evitar novas publicações quando não houver avanço relevante.

Este documento define o fluxo editorial; não configura monitoramento automático nem publica em redes sociais.
